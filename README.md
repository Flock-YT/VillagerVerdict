# Villager Verdict 1.0.0

Minecraft 26.3 的 Fabric 客户端模组，用于记录村民交易、比较商品成本、规划交易所保留名单。服务端无需安装本模组。构建和真实单人服务器集成测试结果见 [TEST_REPORT.md](TEST_REPORT.md)，69 项能力对照见 [FEATURES.md](FEATURES.md)。未验证的验收项不视为通过。

## 安装与使用

需要 Java 25、Minecraft 26.3、Fabric Loader 0.19.5 和 Fabric API 0.163.0+26.3。将 `build/libs/VillagerVerdict-1.0.0.jar` 与对应 Fabric API 放入客户端 `mods` 目录。不需要额外运行库。请使用匹配的 Minecraft 版本。面向 Minecraft 26.4 的模组（例如 `gugle-carpet-addition` 的 26.4 snapshot 构建）不能与此版本同时加载；请移除它或换用 26.3 构建。

- 默认只有 F8 打开管理界面；扫描、标记、导航、取消查找和探测快捷键默认未绑定，可在管理界面的“快捷键”页修改、清除或恢复默认。原版按键列表只显示“打开管理界面”，分类名为 Villager Verdict。管理键原有改绑保留；其余五项使用独立配置，首次升级全部未绑定，不导入旧游戏配置中的 F9/F10。
- 右键村民正常打开交易窗口后，模组记录服务器同步的当前交易。不会推测尚未解锁的交易。
- 只处理当前扫描半径内、已加载且存活的成年职业村民。范围外村民不参与比较，不出现在搜索、列表、统计或导航中；区域分析也只使用附近村民。
- 点击村民查看全部已知交易、物品提示、基础/当前价格、第二输入、库存、最近读取时间、备注、标签及替代依据。替代依据可点击跳转；“定位”关闭界面并只显示目标村民的轮廓与头顶标记，持续到更换目标或取消。再次按定位快捷键、取消查找快捷键或管理界面的“取消查找”按钮可恢复普通标记；查找遵循显示标记总开关，不显示坐标、距离或左上角指引。“下一未扫描”选择最近尚未读取交易的对象。
- 设置页的“职业筛选”支持逐职业开关、全选和全不选，默认全部开启。关闭的职业不扫描、不显示、不参与列表、统计或全局／区域分析；历史数据保留，重新开启后复用有效缓存。职业选择先保存到设置草稿，再保存设置生效，取消不会修改配置。
- 可按职业、物品、附魔、等级、价格、UUID、备注和标签搜索；支持价格、附魔等级、距离、职业及综合价值排序。不同货币先分组，不套兑换率。
- 详情的“编辑”提供自动、始终保留两种模式，以及备注和标签。这些个人设置仅在村民留在扫描范围内时有效；离开范围或退出世界后清空。
- 默认目标列表为空，覆盖所有已知商品。目标编辑使用物品/附魔注册 ID；价格上限为每单位输出对应的各项输入资源上限，0 表示不限。“最少保留数量”包含主力，例如 2 表示保留两名不同村民。
- “区域”创建当前维度内的轴对齐长方体；点击区域名称查看区域记录，点击其“目标”编辑独立清单。目标页面上方可切换全局和区域。重叠区域独立计算。
- 滚轮、Page Up / Page Down 滚动；表单右上角上下按钮也可翻页。Tab 切换原生控件焦点。逻辑宽度达到 640 时列表和详情并排，小窗口使用独立详情页。
- 游戏内管理页及设置、快捷键、数据管理和确认框均使用透明背景，不模糊游戏画面；详情、表单和统计区域保留局部半透明底色。未加载世界时保留原版菜单背景。
- 在游戏内使用扫描、标记和探测快捷键时，快捷栏上方会显示约 3 秒的操作结果，包括标记开启/关闭、扫描附近人数、探测开启/暂停及授权取消。提示支持中英文，不写入聊天记录；自动扫描和自动导航不会反复提示。

## 自动探测

默认关闭。首次为服务器启用时，界面说明额外交互请求并要求选择；设置按服务器身份保存。只有一个“开启/暂停自动读取”开关：开启后立即读取并记住自启；暂停同时停止读取并关闭自启。启用后关闭管理界面才会探测。

只在无 GUI、菜单处于玩家基线、光标为空、未使用物品、未潜行且目标处于正常可达范围、无遮挡时发起正常交互。允许主副手持有普通物品；命名牌和刷怪蛋会避让到另一只手，两手均为这类物品时等待。默认请求间隔 100 毫秒、超时 5 秒、单个村民成功读取后冷却 30 秒。已扫描村民仍持续轮询，优先未扫描或最久未读取的对象；不再设置快照过期时间。失败依次退避 30、60、120、240、300 秒；三次连续超时停止自动探测。超时不等于服务器明确拒绝。新加载的村民无需等待周期扫描即可进入探测队列；每次仍须等上一位交易与菜单内容同步、关闭菜单后才能探测下一位，实际速度受网络和服务器响应限制。

一次只有一个交互上下文。连接代次、维度、UUID、实体 ID、商人菜单类型和容器 ID 必须匹配。无界面探测保留原版 MerchantMenu 创建和内容同步，待交易包和菜单内容同步完成后，仅关闭仍由请求持有且输入槽/光标为空的菜单。完成指关闭请求已发送且本地菜单恢复，不代表服务器发出了关闭确认。冲突、取消、晚到包和异常时放弃关联；隐藏菜单在可确认仍持有时恢复显示，人工窗口优先。不会购买、出售、点击槽位或自动填充交易。

## 分析规则

基础成本用于长期比较，实际成本用于当前优惠。双输入使用成本向量，绿宝石、钻石等资源之间不换算。相同商品按单位输出归一化。物品组件保留，附魔按项比较；为避免漏掉额外附魔的价值，附魔集合不一致时保守地分组。已知更高等级优先于价格，因此更贵的高级交易也可替代低级交易；同等级再比基础成本。最高等级超出目标价格上限时仍保留，并显示价格条件未满足。

推荐采用确定性的贪心多重覆盖和冗余移除，并按资源成本向量和 UUID 确定顺序，**不保证数学最优**。除了商品覆盖和备份数量，还保证每种商品至少保留一份最佳已知交易；同级多输入交易保留互不占优的价格方案，再移除不再需要的村民。备份可以来自价格不同的村民，受价格上限约束时报告不足。状态只有“保留”“不保留”“未扫描”：绿色表示保留，红色表示不保留，黄色表示还没有首次可发布的分析结论。首次读取后继续黄色，计算完成才更新红绿；后续重读期间保持上次颜色。离开范围的村民立即退出比较，剩余村民重新分析；远处交易缓存不参与。低级村民开出更好的附魔后，下次自动读取会重新分析，必要时从红色变成绿色。有目标清单时，不在目标范围内的村民可以不保留。

设置可分别控制状态标记、摘要、提醒及颜色，并保留显示标记总开关。开启标记时，实体轮廓和隔墙显示固定启用，不再提供独立开关。仅有职业的成年村民会进入扫描、存储、分析和管理列表；失业村民、傻子村民和幼年村民直接忽略。获得职业后在下一次扫描纳入，失去职业后清理记录与标记，转职后重新采集交易。扫描半径内所有符合条件的已加载村民都会生成标记，不受旧标记数量上限或旧文字距离设置影响；实体显示仍遵循游戏本身的加载和渲染范围。原版或其他模组已有轮廓色不被本模组覆盖。颜色配合状态文字或符号。

头顶标记居中逐行显示状态、村民等级及该职业已知的标志性高阶交易，例如：

```text
保留
等级：1
经验修补
保护4
耐久3
```

图书管理员只列附魔书中的附魔，同种附魔只保留已知最高等级；最大等级为 1 的附魔省略数字。装备匠只列对应的钻石装备，其他职业的筛选范围见 [职业标记规则](FEATURES.md#职业标记规则)。物品不显示价格或数量，未采集或没有符合条件的交易时仅显示状态和等级。原有自定义名称保留在标记上方。关闭状态标记时隐藏状态行；关闭交易摘要时仅保留状态符号；两项都关闭时不添加文字，轮廓仍受标记总开关控制。

## 数据与构建

数据位于游戏目录 `config/villagerverdict/`，配置和世界数据使用带版本 JSON；内部快捷键单独保存在 `config/villagerverdict/shortcuts.json`。世界文件名为身份哈希，身份包含服务器地址或本地存档绝对路径、数据集名称、维度；缓存再按 UUID 区分。服务器后台世界切换无法由原版协议可靠识别，需在设置中修改本地数据集名称隔离。单人存档移动路径后视为不同身份。世界数据版本为 4，仅持久保存 UUID、职业和交易快照组成的缓存，以及目标和区域；不保存坐标、备注、标签、人工模式或推荐结论。再次检测到同一 UUID 且职业一致时可复用交易，并重新计算附近推荐。确认死亡或失去职业时删除缓存；普通卸载保留缓存。管理界面的“数据”页可以清空指定世界或整个服务器的交易缓存与当前活动记录，目标和区域设置会保留。清空后交易信息需重新交互获取。旧开发格式不迁移，读取失败仍保护原文件。自动扫描开启时会在下一轮扫描恢复附近活动记录。旧配置的 `markerLimit`、`textRange` 字段继续读取，但不再限制标记。

每名村民仅保留最新快照。变化只在内存比较，不保存历史；通知按最新交易指纹去重。单写入线程合并写入并原子替换；读取损坏文件后该文件受写保护，错误保留在日志中，不会用空数据覆盖。修复或备份移走损坏文件后重新连接/重启。业务分析在线程中使用不可变副本，回到客户端前校验世界代次和数据更新状态。渲染只读取 tick 阶段准备的标记。

```sh
# JAVA_HOME 应指向 Java 25 的安装目录
./gradlew clean build
./gradlew runClient
./gradlew runClientGameTest
```

Gradle Wrapper 9.6.1、稳定 Fabric Loom 1.17.21、Mojang 非混淆类名；没有 Yarn 映射。`src/main` 是普通 Java 模型/算法/存储/协议状态机，`src/client` 是 Fabric 和 Minecraft 适配。JUnit 在 `src/test`；独立客户端集成测试模组在 `src/gametest`，不打入发布 JAR。集成测试只在 `build/run/clientGameTest` 创建并清理测试存档，不操作玩家存档。运行测试不自动接受专用服务器 EULA。
