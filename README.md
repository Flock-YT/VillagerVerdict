# Villager Verdict 1.0.0

Minecraft 26.3 的 Fabric 客户端模组，用于记录村民交易、比较商品成本、规划交易所保留名单。服务端无需安装本模组。构建和真实单人服务器集成测试结果见 [TEST_REPORT.md](TEST_REPORT.md)，69 项能力对照见 [FEATURES.md](FEATURES.md)。未验证的验收项不视为通过。

## 安装与使用

需要 Java 25、Minecraft 26.3、Fabric Loader 0.19.5 和 Fabric API 0.163.0+26.3。将 `build/libs/VillagerVerdict-1.0.0.jar` 与对应 Fabric API 放入客户端 `mods` 目录。不需要额外运行库。请使用匹配的 Minecraft 版本。面向 Minecraft 26.4 的模组（例如 `gugle-carpet-addition` 的 26.4 snapshot 构建）不能与此版本同时加载；请移除它或换用 26.3 构建。

- 默认只有 F8 打开管理界面；扫描、标记、导航和探测快捷键默认未绑定，可在管理界面的“快捷键”页修改、清除或恢复默认。原版按键列表只显示“打开管理界面”，分类名为 Villager Verdict。管理键原有改绑保留；其余四项使用独立配置，首次升级全部未绑定，不导入旧游戏配置中的 F9/F10。
- 右键村民正常打开交易窗口后，模组记录服务器同步的当前交易。不会推测尚未解锁的交易。
- “实时附近”只显示三维距离内的已加载村民；“全部记录”显示当前数据集和维度的持久记录。卸载村民仅有最后位置和时间。
- 点击村民查看全部已知交易、物品提示、基础/当前价格、第二输入、库存、完整度、备注、标签及替代依据。替代依据可点击跳转；“定位”关闭界面并显示目标坐标和距离。“下一待检查”选择最近待检查对象。
- 可按职业、物品、附魔、等级、价格、UUID、备注和标签搜索；支持价格、附魔等级、距离、职业及综合价值排序。不同货币先分组，不套兑换率。
- 详情的“编辑”提供自动、手动保留、保护、手动淘汰状态。保护和保留固定纳入；淘汰排除于推荐并报告缺口。变更人工状态会替换原状态。
- 默认目标列表为空，覆盖所有已知商品。目标编辑使用物品/附魔注册 ID；价格上限为每单位输出对应的各项输入资源上限，0 表示不限。“最少保留数量”包含主力，例如 2 表示保留两名不同村民。
- “区域”创建当前维度内的轴对齐长方体；点击区域名称查看区域记录，点击其“目标”编辑独立清单。目标页面上方可切换全局和区域。重叠区域独立计算。
- 滚轮、Page Up / Page Down 滚动；表单右上角上下按钮也可翻页。Tab 切换原生控件焦点。逻辑宽度达到 640 时列表和详情并排，小窗口使用独立详情页。

## 自动探测

默认关闭。首次为服务器启用时，界面说明额外交互请求并要求选择；设置按服务器身份保存。“暂停”保留启用偏好但停止当前连接的工作，“关闭”同时取消启用偏好。启用后关闭管理界面才会探测。

只在无 GUI、菜单处于玩家基线、光标和双手为空、未潜行且目标处于正常可达范围、无遮挡时发起正常交互。默认请求间隔 2 秒、超时 5 秒、村民冷却 30 秒、成功缓存 30 分钟。失败依次退避 30、60、120、240、300 秒；三次连续超时停止自动探测。超时不等于服务器明确拒绝。

一次只有一个交互上下文。连接代次、维度、UUID、实体 ID、商人菜单类型和容器 ID 必须匹配。无界面探测保留原版 MerchantMenu 创建和内容同步，待交易包和菜单内容同步完成后，仅关闭仍由请求持有且输入槽/光标为空的菜单。完成指关闭请求已发送且本地菜单恢复，不代表服务器发出了关闭确认。冲突、取消、晚到包和异常时放弃关联；隐藏菜单在可确认仍持有时恢复显示，人工窗口优先。不会购买、出售、点击槽位或自动填充交易。

## 分析规则

基础成本用于长期比较，实际成本用于当前优惠。双输入使用成本向量，绿宝石、钻石等资源之间不换算。相同商品按单位输出归一化。物品组件保留，附魔按项比较；为避免漏掉额外附魔的价值，附魔集合不一致时保守地分组。已知更高等级优先于价格，因此更贵的高级交易也可替代低级交易；同等级再比基础成本。最高等级超出目标价格上限时仍保留，并显示价格条件未满足。

推荐采用确定性的贪心多重覆盖和冗余移除，并按可用性、资源成本向量和 UUID 确定顺序，**不保证数学最优**。备份可以来自价格不同的村民，受价格上限约束时报告不足。绿色代表推荐/保护，黄色代表未检查、过期或无法确认，红色要求每条已知交易均有替代依据。未满级的红色建议为低置信度，存在未知交易风险。仅有卸载或过期替代者时不会显示“当前替代者可用”。

设置可分别控制状态标记、摘要、轮廓、隔墙、提醒及颜色；默认隔墙关闭。扫描半径内所有已加载村民都会生成标记，不受旧标记数量上限或旧文字距离设置影响；实体显示仍遵循游戏本身的加载和渲染范围。原版或其他模组已有轮廓色不被本模组覆盖。颜色配合状态文字或符号。

## 数据与构建

数据位于游戏目录 `config/villagerverdict/`，配置和世界数据使用带版本 JSON；内部快捷键单独保存在 `config/villagerverdict/shortcuts.json`。世界文件名为身份哈希，身份包含服务器地址或本地存档绝对路径、数据集名称、维度；记录再按 UUID 区分。服务器后台世界切换无法由原版协议可靠识别，需在设置中修改本地数据集名称隔离。单人存档移动路径后视为不同身份。管理界面的“数据”页可以清空指定世界或整个服务器的村民记录，目标和区域设置会保留；重新扫描会按当前已加载的村民建立新记录，交易信息需重新交互获取。自动扫描开启时会在下一轮扫描恢复记录。旧配置的 `markerLimit`、`textRange` 字段继续读取，但不再限制标记。

每名村民仅保留最新快照。变化只在内存比较，不保存历史；通知按最新交易指纹去重。单写入线程合并写入并原子替换；读取损坏文件后该文件受写保护，错误保留在日志中，不会用空数据覆盖。修复或备份移走损坏文件后重新连接/重启。业务分析在线程中使用不可变副本，回到客户端前校验世界代次和数据更新状态。渲染只读取 tick 阶段准备的标记。

```sh
# JAVA_HOME 应指向 Java 25 的安装目录
./gradlew clean build
./gradlew runClient
./gradlew runClientGameTest
```

Gradle Wrapper 9.6.1、稳定 Fabric Loom 1.17.21、Mojang 非混淆类名；没有 Yarn 映射。`src/main` 是普通 Java 模型/算法/存储/协议状态机，`src/client` 是 Fabric 和 Minecraft 适配。JUnit 在 `src/test`；独立客户端集成测试模组在 `src/gametest`，不打入发布 JAR。集成测试只在 `build/run/clientGameTest` 创建并清理测试存档，不操作玩家存档。运行测试不自动接受专用服务器 EULA。
